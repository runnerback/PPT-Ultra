# PPT Ultra 1.2.1 — Compact skill uploads and page-number controls

PPT Ultra now includes a lossless upload package for platforms limited to 500 files. All engines, templates and assets remain available, and hosts can explicitly control whether generated decks show page numbers.

## Highlights

- **268 uploaded files, about 51 MB**: readable workflows and reference documents plus a verified archive containing the complete original skill.
- **No resource pruning**: all 13,375 runtime files are restored with their original content and paths.
- **Page-number controls**: host briefs and Spec Native specifications can explicitly disable page numbers.

## What's new

### Compact distribution

- `tools/package-upload.py` builds an upload ZIP with `SKILL.md` directly at its root, rejects builds over 500 uploaded files or 100,000,000 bytes, and writes a SHA-256 checksum alongside the ZIP. It also checks the size after expanding the outer ZIP.
- `bootstrap.py` verifies the bundled archive and each restored file before returning the original skill directory. It uses only Python's standard library, supports a writable cache outside the upload directory, and reuses that cache on subsequent calls.
- `tools/test_upload_package.py` checks lossless restoration, cache reuse, corruption detection and unsafe archive paths. Its `--smoke` option runs the existing engine and host tests against the restored skill.

### Page numbers

- Host briefs accept `constraints.page_numbers` (default `true`). When set to `false`, prompts request no page numbers and `collect_manifest.py` checks PPTX source SVGs or HTML chrome for remaining page-number text.
- Spec Native accepts top-level `page_numbers: false`, suppressing generated page numbers on all slide types. The image example and smoke suite cover this option.

### Release automation

- Tag-triggered releases publish both the full directory ZIP and the compact upload ZIP, with a shared `SHA256SUMS` file.
- Release status logging no longer requests the unsupported `isLatest` JSON field from `gh release view`.

## Lessons

Most files belong to the icon library; removing caches or duplicate content alone cannot meet a 500-file limit. Compact packaging preserves resource coverage while the bootstrap step restores the paths expected by the existing engines.

## Upgrade notes

- Use `ppt-ultra-1.2.1-upload.zip` for a file-count-limited upload form, and `ppt-ultra-1.2.1.zip` for conventional local skill-folder installation.
- The compact format requires a host that allows Python execution, bundled `.tar.gz` resources and a writable runtime cache. Initialization does not install route dependencies; Python/Node dependencies are still required by the selected workflow.
- The expanded runtime still contains 13,375 files and occupies about 101 MB. Hosts that recursively count archive contents or limit runtime file counts require platform-side support; acceptance by a particular upload platform is not guaranteed.
- Original runtime instructions, engine code and assets are preserved. Existing page-number behavior remains the default unless explicitly disabled.

- Existing smoke suite on the restored skill: attribution guard, all five Spec Native examples, style-brief consistency, page-number controls, PPTX/HTML host contracts and Editorial runtime synchronization.
- Optional LibreOffice rendering was not run because LibreOffice was unavailable in the local test environment.
