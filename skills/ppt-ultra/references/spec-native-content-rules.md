# Spec Native · 内容规则

这些规则来自两个月真实汇报迭代里被反复要求的东西。写规格时逐条对照；其它路线写页面文案时也可借用。

## 1. 标题与结论条

- **标题必须是判断句**：主体 + 结论 / 数字。「组织现状」不行；「一支 92 人的团队扛 118 个车型」可以。
- **每页 takeaway 要回答「所以呢」**：带数字、或带明确动作 / 请示；不能复述标题。
- 每章第一页先说这章的结论，每章最后一页落到动作 / 下一步；总结页只放判断句结论与请示。
- 标题不带书名号，不出现「本页 / 上一页」这类指代。

## 2. 禁止空话

「持续推进、不断完善、进一步加强、赋能、抓手、稳步、全面提升」这类不带对象和数字的词一律不用。写不出数字就写定性判断 + 原因。

## 3. 数字纪律

- 数字必须带口径与时间：人数写口径（在编 / 外包）、比例写分母、对比写基线（同行 / 上期 / 目标）与测算时间。
- 对比页必须给基线；没有基线的「提升」不要写成数字。
- 榜单 / 排名类数据只能说明它本身的口径，不能当成工作量、饱和度等其它口径的证据。
- 图表只在有 3 个以上可比真实数值时用；没有真实数字绝不能用示意值凑图（引擎会把全相同数值判为假数据拒绝）。

## 4. 出处角标

- 凡取自资料的数字、表格行、图表数据、关键结论，在该条文字末尾带 `[n]`（可多个 `[2][5]`），编号与 `references` 一致。
- 资料没有的内容不要编号；资料写「未覆盖」的，不要用示意数字凑，改定性表述并在交付说明里写明缺什么。
- 引用出处页由引擎自动追加在最后，不计入有效页数，规格里不要写。

## 5. 版式选择

| 内容形态 | 优先版式 |
|---|---|
| 3~6 条并列要点 | `bullets`；分组后有小标题 → `cards` |
| 2~5 个关键数字 | `numbers`；数字 + 一张趋势 / 对比图 → `kpi` |
| 多维度对照 | `table`（≤7×5）；首列是厂商 → `logo_table` |
| 有真实可比数值 | `chart`（按 §3 选类型） |
| 有先后顺序的步骤 | `flow`（LR）；跨角色 / 系统 → `swimlane`；系统间调用 → `sequence` |
| 上下级 / 分解 | `hierarchy`；分层架构 → `layers` |
| 时间推进 | `timeline`（3~8 个里程碑，带 done / doing / todo） |
| 闭环 / 周期 | `cycle` |
| 转化 / 漏斗 | `funnel` |
| 两方案取舍 | `compare`；单方案利弊 → `pros_cons`；两维度分类 → `matrix` |
| 当事人原话 | `quote`（原样引用并注明来源） |
| 截图 / 原图 | `image`；图 + 要点 → `image_split`；多图 → `image_grid`；图上指点 → `image_callout`；章节大图 → `image_bg` |
| 多家厂商 | `vendors`（2~4 家） |

- **版式要变化**：连续 3 页不要同一 layout；有效页 ≥8 时至少 1 页 `section` 分章。
- 一页只讲一件事；要点之间是并列或递进，不混放。
- 术语原样保留；中文为主时不中英混杂同一概念。

## 6. 页数口径

用户说的页数是**有效页数**（不含封面、封底）。规格里的 slides = 封面 1 页 + 有效页；封底「谢谢」页和引用出处页由引擎追加。推荐 5~12 页有效页，材料明显多或用户要求详细才增。

## 7. 交付说明

生成后给用户一段说明：页数、哪些页用了图表 / 图示、哪些数字没有出处或缺口径、做了哪些假设（非交互时尤其要写）。不要把未达标写成「已完成」。
